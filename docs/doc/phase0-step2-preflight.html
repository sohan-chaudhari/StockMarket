Risk VectorAssessment
In-process historical service login Safe — historical_service.login() has a session-sharing guard: if angelone_service.is_logged_in and same api_key, it reuses the live JWT without calling generateSession()
Standalone script execution (recovery script) Critical — standalone script has its own AngelOneService instance that is NOT logged in; login() calls generateSession() fresh → AngelOne invalidates the live app's JWT → WebSocket disconnects → live tick feed stops
Live TP/SL execution during disconnection Risk — if WS disconnects mid-market, stop-loss triggers based on live ticks will pause until reconnect; pending orders are on the exchange, not locally managed, so they remain active but new alerts won't fire
Candle builder during recovery inserts Safe — live candle builder uses ON CONFLICT DO UPDATE for its own ticks; recovery uses DO NOTHING; no lock contention expected
Auth / JWT during off-hours recovery Safe — AngelOne JWTs are valid for 24h; calling generateSession() during off-hours (before 09:00 or after 16:00 IST) will not disrupt a live feed because the WS subscription loop is dormant outside NSE market hours
Required Execution Window

The live app can remain running; its WS token will be replaced by the recovery login, but the reconnect logic in angelone_service.ensure_connection() will re-authenticate and re-subscribe automatically when the next market session opens.
